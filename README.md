# 네이버 폐지 줍기 - 사용자 관리 버전

원본 ff_naverpaper를 기반으로 시놀로지 FF 환경에서 안정적으로 운영하기 위해 보완한 버전입니다.

원본 저장소는 upstream으로 유지하고, 이 저장소를 origin으로 사용합니다. 원본 업데이트가 필요한 경우 변경사항을 검토한 뒤 선택적으로 병합하는 방식으로 관리합니다.

## 추가 보완 사항

### 네이버 로그인 및 쿠키 안정화

- 일부 계정에서 NID_AUT, NID_SES가 세션 쿠키로 발급되는 경우 실행용 저장 쿠키를 영속 형태로 보정합니다.
- 실행 중 로그인 상태가 깨져 불완전한 쿠키만 남은 경우 기존 정상 쿠키를 덮어쓰지 않습니다.
- 프로필의 설정 저장만 눌렀을 때 예전 쿠키가 실행용 쿠키 파일로 다시 살아나는 문제를 방지합니다.
- 프로필의 로그인 버튼으로 새 로그인이 성공하면 새 NID_AUT, NID_SES, NID_JST를 프로필 설정에도 반영합니다.
- 로그인 전용 비동기 이벤트 루프를 안정적으로 재사용하도록 보완했습니다.

### 방문기록 처리 보완

실제 적립에 실패했는데도 URL을 방문 완료로 기록하면 다음 실행부터 해당 URL이 계속 Skip 되는 문제가 있었습니다.

현재는 다음과 같이 처리합니다.

- 실제 방문 성공(visited)만 방문 완료 기록
- already received once처럼 이미 1회 적립이 끝난 것이 확실한 경우는 종결 기록으로 유지
- 로그인 화면 리다이렉트, 오류, 일반 Skip은 방문 완료로 저장하지 않음

## 계정별 방문기록 관리

계정 설정 화면의 각 프로필에 방문기록 관리 기능이 추가되어 있습니다.

### 오류 방문기록 복구

과거 오류 때문에 방문 완료로 잘못 저장된 기록만 찾아 삭제합니다.

복구 후보 조건은 다음과 같습니다.

- 해당 계정의 실행 결과가 방문 0건
- 해당 실행의 예상 적립 포인트가 0점
- 해당 실행 시간 안에 url_visits가 저장됨
- 단, 실제 visited 상세기록 또는 already received once 기록은 제외

다른 계정의 방문기록, 정상 방문기록, 쿠키, 프로필 설정, 과거 실행결과는 삭제하지 않습니다.

### 방문기록 전체 초기화

선택한 프로필의 url_visits만 모두 삭제합니다.

다음 데이터는 유지됩니다.

- 다른 프로필의 방문기록
- 네이버 로그인 쿠키
- 계정/프로필 설정
- 수집 실행 이력
- 실행 상세 결과
- 캠페인 URL 목록

이미 정상 적립한 URL도 다음 실행에서 다시 확인할 수 있으므로 필요한 경우에만 사용하는 기능입니다.

## 안전장치

방문기록을 실제로 삭제하기 전에 다음 절차를 자동으로 수행합니다.

1. 삭제 대상 계산
2. SQLite 온라인 백업 생성
3. 삭제 대상 재확인
4. 선택된 계정의 방문기록만 삭제
5. 삭제 결과 검증
6. 완료 상태 표시

백업 파일은 data/backup/에 저장하며 방문기록 관리용 백업은 최근 10개를 유지합니다.

포인트 수집 중에는 방문기록 삭제를 시작할 수 없고, 방문기록 정리 작업 중에는 포인트 수집과 로그인을 시작하지 못하도록 상호 배제 처리되어 있습니다.

## 진행상태 표시

방문기록 작업은 패키지 설치 작업과 비슷하게 백그라운드 Job으로 실행됩니다.

계정 화면에서 다음 상태를 확인할 수 있습니다.

- 진행률(%)
- 현재 단계
- 현재 작업 설명
- 대상 건수
- 삭제 건수
- 백업 파일명
- 단계별 작업 로그

작업이 끝나면 방문기록 현황을 자동으로 다시 조회합니다.

## 테스트

- already received once 기록이 보존되는지
- 선택하지 않은 다른 프로필의 방문기록이 보존되는지
- 전체 초기화가 선택 프로필에만 적용되는지
- 삭제 전 백업에 원본 데이터가 보존되는지
